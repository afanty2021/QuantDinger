# qlib Tier 0 暴露价格复权基准修正方案（2026-09-13）

状态：**设计评审稿**。修正 `docs/qlib-market-data-adapter-20260912.md` 中"暴露价格语义"的决策：该决策依据的"现有腾讯层同为前复权（qfq），qlib 存储值原样暴露即可"假设，经 2026-09-13 实测**证伪**。本方案在不动 Tier 0 架构与覆盖语义的前提下，仅改换算层。

## 1. 问题：实测证伪原假设

### 1.1 investment_data 的真实存储语义

对 sh600519（2026-09-11 包，`np.fromfile` 独立读 bin）实测：

| 日期 | qlib 存储价 | factor | 原始价 (=存储÷factor) | 腾讯 qfq | 腾讯不复权 |
|---|---|---|---|---|---|
| 2026-04-22 | 334.8759 | 0.237585 | 1409.5000 | 1381.476 | — |
| 2026-06-25 | 287.9767 | 0.237585 | 1212.1000 | — | — |
| 2026-06-26（除息） | 284.2200 | **0.243208** | 1168.6300 | — | — |
| 2026-09-11 | **310.1288** | 0.243208 | **1275.1600** | **1275.160** | **1275.160** |

关键事实：

1. **factor 全程 < 1，且最新行也不是 1**（≈0.243，量级 = 上市以来累计分红调整的倒数）。
2. 除息日（2026-06-26）factor 跳增（0.237585 → 0.243208），**存储序列连续**（287.98 → 284.22，无跳空），原始价跳空（1212.10 → 1168.63，-3.6% 即分红幅度）。
3. `raw = stored ÷ factor` 逐位还原腾讯不复权价（2026-04-22 的 1409.5000/26916 与 2026-09-11 的 1275.16 双向验证）。

结论：investment_data 的存储语义是**归一化的累计复权**（类后复权：整条序列除息连续、日收益率即真实收益率，再乘以固定归一化常数使数值量级接近现价），**不是**券商式"锚定今日"的前复权。原设计文档"复权一致性决策"表中"现有腾讯层同为前复权；复权价收益率序列可直接用于回测"——收益率部分正确，**量级部分错误**。

### 1.2 造成的实际影响

Tier 0 暴露 stored 原样，腾讯层暴露 qfq（锚今日，最新行 = 原始价）。同一时刻同一标的：

- qlib 层最新收盘 = **310.13**，腾讯层 = **1275.16**，**量级差 4.11×**。
- 本地数据新鲜时（当前日历到 2026-09-11），严格模式 Tier 0 **优先出数**，因此：
  - 图表/K 线显示的绝对价格错误 4.11×；
  - `KlineService.get_realtime_price` 的 1D K 线回退定价路径错误 4.11×（组合估值、paper 盘定价受影响）；
  - 回测入场/出场价、止损位等绝对价格语义全部错误；
  - 仅涨跌幅/动量等收益率类指标正确（复权序列连续）。

## 2. 目标与非目标

目标：

1. Tier 0 暴露价格的**量级与在线层（腾讯 qfq）一致**：最新行 = 原始价（1275.16），跨层切换/对比无 4× 跳变。
2. 保留除息日连续性（回测正确性硬约束，与原设计一致：禁止拼接的"复权基准一致"原则不变）。
3. 不改动窗口推导、覆盖判定、新鲜度、严格/宽松模式、线程模型与缓存结构（本次只改换算层）。

非目标：

- 不还原"真正的原始价"作为暴露语义（原始序列除息跳空，回测收益错误，见方案对比）。
- 不处理 ETF/指数/分钟线（维持原设计非目标）。
- 不改动在线层的复权实现。

## 3. 修正后的换算公式

### 3.1 价格

设包内某标的 factor 序列为 `f[0..N-1]`（`N-1` 为最新行），归一化锚取包尾 `f_last = f[N-1]`：

```text
exposed_price[t] = stored_price[t] × (f[t] / f_last) = stored_price[t] ÷ f_last
```

右边等价形式揭示了实现极简：**每行只需除以同一个标量 `f_last`**（`f[t]` 与 stored 相乘后相消——stored 本身已含 `raw × f[t]`）。

性质验证（sh600519 实测）：

- 2026-09-11：310.1288 ÷ 0.243208 = **1275.16** = 原始价 ✓（锚在包尾，最新行还原为原始价，与腾讯层量级一致）；
- 2026-04-22：334.8759 ÷ 0.243208 = 1376.90，腾讯 qfq 同日 1381.476，差 **0.33%**；
- 除息连续性：`exposed` 是 stored 的逐行正常数缩放，stored 连续 ⇒ exposed 连续 ✓；
- 退化为恒等：factor 恒为 1 的数据（如无分红样本、单测 mini root）⇒ f_last = 1，暴露值 = stored，行为与现状完全一致 ✓。

### 3.2 与腾讯 qfq 的 0.33% 方法差（已知且接受）

同为"锚今日前复权"，investment_data（yahoo 式 adjclose 比率法）与腾讯（逐次 `(p-d)/p` 减法滚动）在现金分红处理上有方法差异，且随历史分红次数累积（实测 4 个多月差 0.33%）。接受理由：跨层量级一致是硬需求，逐位一致不可能；切换数据层本就伴随复权方法差异（在线层之间切换同样存在）；禁止拼接规则已保证单序列内部一致。

### 3.3 成交量

腾讯层 volume 为**原始量**，为跨层一致，Tier 0 改为还原原始量：

```text
exposed_volume[t] = stored_volume[t] × f[t]     # raw = stored / factor 的逆：量 = 存储 × factor
```

实测：2026-04-22 stored 113290 × 0.237585 = 26916.4 ≡ 腾讯原始量 26916 ✓。周线聚合的 volume 求和在**还原后**进行（跨除息周的每周量 = 周内原始量之和，与腾讯 weekly 语义一致）。

## 4. 否定方案

| 方案 | 否定理由 |
|---|---|
| B1：暴露原始价（stored ÷ f[t]） | 除息日跳空（6-26 -3.6%），回测收益率被分红污染——违反回测正确性硬约束 |
| B2：维持现状 + 文档警告 | 绝对价格错 4.11×，估值/定价路径直接错误，不可接受 |
| B3：暴露后复权（stored 原样）+ 前端/服务层整体缩放 | 前端在私有仓库不可控；服务层缩放即方案 A，无区别 |
| B4：锚定"今天"逐请求动态重算（用实时 factor） | investment_data 仅 EOD 全量包，无盘中 factor；锚包尾（最新已完成交易日）与腾讯 qfq 日线锚一致，无增益 |

## 5. 模块改动

### 5.1 `app/data_sources/qlib_cn.py`（换算层，唯一行为变更点）

- `_DAILY_FIELDS` 不变（open/close/high/low/volume）；新增读取 `factor` 字段（走现有 `read_field`，享受同一 LRU）。
- `_fetch` 读到五字段后增读 factor：**factor bin 缺失/损坏、`f_last` 非有限或 ≤ 0 → 整体 `None` fall through**（不得默默把累计复权价当 qfq 供出）。
- 行构造改为：OHLC 各 `÷ f_last`，volume `× f[t]`（用该行自己的 factor，不是 f_last）；round 精度不变（OHLC 4 位、volume 2 位）。
- 停牌 NaN 判定、窗口推导、覆盖/新鲜度判定、周线聚合结构、LRU/文件戳热加载——全部不变。
- 模块 docstring 与 "Storage semantics" 注释更新为修正后的语义（含 2026-09-13 实测依据）。

### 5.2 `app/data_sources/cn_stock.py`

无改动（接线与 filter_and_limit 契约不变）。

## 6. 边界与运维语义

| 场景 | 行为 |
|---|---|
| factor bin 缺失/损坏、f_last ≤ 0/NaN | 整层 fall through（在线层兜底），限频告警 |
| factor 恒 1 的自有数据 | 换算为恒等，行为与现状一致 |
| 除息日当天 | 包内已含新 factor（EOD 全量重发），当日 exposed 序列连续；与腾讯层差 = 两家方法差（<1%） |
| 包更新（EOD）后 f_last 变化 | 全部历史 exposed 值同步微调（qfq 固有，腾讯层同此行为）；KlineService 缓存 TTL 内的旧值随过期自然替换 |
| 盘中（包尚未更新） | 锚 = 最新已完成交易日，与腾讯 qfq 日线锚一致 |
| 回滚 | 还原 qlib_cn.py 换算行为 stored 原样即可；无迁移/无配置变更/无在线层影响 |

## 8. 开放问题（请评审定夺）

1. **volume 语义**：本方案选择"还原原始量"（与腾讯层一致）。另一选项是保持 stored 量原样（自洽的"复权量"序列，但与在线层量纲系统性偏离）——是否同意以"跨层一致"优先？
2. **factor 缺失的容忍度**：本方案选择缺失即 fall through（保守）。若用户自有数据无 factor 列，Tier 0 将完全不可用（现状可用）——是否需要 `QLIB_CN_TRUST_RAW=1` 之类的逃生门（默认关闭），还是保持严格、文档引导用户补 factor？
3. **verify 脚本 `--qfq` 对照的容忍度**：1% 是否合适（近端 0.33%，早年可能累积超差）？
